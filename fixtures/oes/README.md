# OES scoreboard corpus (D-013)

Test data for the OES decoder (`crates/noplayout-decoder-oes`, milestone M4.5). M4.5 is done when the
Rust decoder reproduces every vector here byte for byte.

## Where it comes from

Ported in M0 from Caleb's own project `unc-virtual-score-server` (MIT, © 2023 furrymayo) at commit
`001153b757e2087b02ca47a328f48d93f120a6b7`. Only protocol data and test vectors were taken; that
project's documentation, configuration and venue data were not.

| Here | Upstream | Changes |
|---|---|---|
| `reference/protocol.py` | `website/protocol.py` | none (byte-identical) |
| `reference/test_protocol.py` | `tests/test_protocol.py` | none (byte-identical; it imports `website.protocol`, so it documents the cases rather than running here) |
| `reference/simulators/oes_helpers.py`, `sim_*.py` | `simulators/` | none (byte-identical; `run_all.py` not taken) |
| `reference/LICENSE-MIT` | `LICENSE` | none |
| `vectors/streams.json` | the per-sender UDP framing tests in `tests/test_ingestion.py` | re-derived, not copied: venue names removed, real sender addresses replaced with RFC 5737 documentation addresses (`192.0.2.10`, `192.0.2.11`) |

The one real capture (a football datagram, 2026-08-12) is kept as bytes; it carries scoreboard data
only. Its source venue and address are not recorded here.

## What is in `vectors/`

Generated by `tools/gen_vectors.py` from the reference decoder, with fixed seeds, so the files are
reproducible (`python3 fixtures/oes/tools/gen_vectors.py` and `git diff` must be empty).

- `<sport>.jsonl`: 240 packets per sport (Basketball, Baseball, Softball, Football, Volleyball,
  Lacrosse, Hockey, Wrestling, Soccer), one JSON object per line: `hex` (the whole packet, STX to CR)
  and `decoded` (what `protocol.identify_and_parse` returns, field for field, strings exactly as
  the reference pads them).
- `streams.json`: framing cases. Each case lists `datagrams` (`sender`, `hex`) and the packets a
  per-sender `PacketStreamParser` frames from them, decoded. Covers the captured datagram, two
  senders, a frame split around another sender's datagram, a foreign fragment that must not be
  spliced in, repeats, and a serial/TCP byte stream in uneven chunks with garbage, a bad type byte
  and a control byte mid-frame.
- `index.json`: per-sport counts, seeds, packet length and type byte.

Fixtures are byte-identical copies or generated files: never reformat them (`.editorconfig`,
`.gitattributes`).
