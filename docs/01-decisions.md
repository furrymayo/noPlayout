| D-006 | 2026-11-26 | Caleb | **Integrated third-party data** must have a home in the UI: a Data Sources area where the operator adds a source (scoreboard over serial, TCP or UDP as the reference examples; later JSON/HTTP poll, CSV/Sheets), sees its live status and values, and maps source fields onto graphic fields (e.g. scoreboard "Main Clock" → scorebug gameClock). The `DataSource` design in IDEA.md §7 must cover serial, TCP (dial-out and listen) and UDP (receive) transports. | Caleb's review of the mockups. |
| D-007 | 2026-11-26 | Caleb | Mockups approved, subject to D-005/D-006 being added. (2) Add always-live hotkey alternates that work inside text fields (e.g. Ctrl+Space = TAKE). (3) Restore prompt: Enter = **Restore**. (4) Preview shows the cued item alone in v1. (5) Wizard: Web and NDI both on by default; NDI only when the runtime is found. (6) Per-channel format kept, under Advanced. (7) Auto-advance after TAKE off by default. | Caleb: "Yes, use Rayleigh's picks." |
| D-008 | 2026-11-26 | Caleb | Scoreboard data sources are **built in v1** (overrides IDEA.md §7 "built later"): DataSource framework, serial + TCP (dial-out/listen) + UDP (receive) transports, field mapping, manual override, health, with at least one real decoder. Franky places it as its own milestone and proposes which decoder(s). | Caleb: "v1". |
| D-009 | 2026-11-26 | Caleb | UI rev 2 approved with Rayleigh's picks on Usopp's 3 questions: (1) when a data source goes quiet/lost, the game clock **holds** its last value with an amber "source lost" light (no local free-run); (2) Take ID entry: **Enter cues, Space takes** (no one-step number+Space take); (3) source **connection settings (port/host) are per computer**, **field mappings are saved with the show**. | Caleb: "approved with your picks". |
| D-010 | 2026-11-26 | Caleb | Research picks approved (Robin `~/OrgWork/research/2026-11-26-noplayout-foundations.md` + addendum): (1) first scoreboard decoder **OES**, second **Daktronics All Sport 5000 RTD**; (2) **RossTalk-compatible listener** (TCP 7788) in v1, off by default; (3) Take IDs **unique within a show**, auto-increment, inline error on duplicate; (4) Separate Fill & Key FILL default **Shaped (premultiplied)**, Unshaped one click away, to be confirmed by a bench test on Caleb's switcher; Fill+Alpha default stays **straight/unshaped BGRA** per NDI (Robin D10); (5) NDI runtime **detected and linked to NDI's installer, not bundled**; (6) Edit-mode preview rendered **through a CEF renderer**, not the Tauri webview; (7) Intel macOS built and tested until GitHub retires Intel runners (~Aug 2027), then build-only; (8) repo licence **Apache-2.0**. Robin's D1-D11 digest is the engineering baseline. | Caleb: "research picks approved". |

| D-013 | 2026-11-26 | Caleb | **OES test data comes from Caleb's existing project** `unc-virtual-score-server` (MIT, Caleb's): `website/protocol.py` decoders, `tests/test_protocol.py` + `tests/test_ingestion.py` vectors (incl. per-sender UDP framing), and `simulators/` (OES encoders + per-sport streams). **No new venue recording is required for M4.5.** Replaces Franky's R11 gate: M4.5 is done when noPlayout's OES decoder passes a test corpus ported from those vectors and simulator streams, byte-for-byte, over serial-loopback/TCP/UDP. Port only protocol data and test vectors; no venue names or addresses from that repo. | Caleb: "just use the OES parsing data from the other project." |
